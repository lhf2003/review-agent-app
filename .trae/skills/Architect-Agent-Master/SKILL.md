# Architect-Agent-Master - 项目架构治理专家

本技能通过标准化的 `AGENT.md` 文档体系，为 AI 代理提供持久化的项目架构记忆，作为"架构守护者"确保项目演进严格遵循工业级规范。

## 核心指令

### `/init` - 初始化架构基座

为项目创建完整的架构文档体系。

**执行流程：**

1. **建立规范体系**
   - 后端：强制遵循《阿里巴巴 Java 开发手册》（命名规约、集合处理、并发控制、异常处理等）
   - 架构设计：明确 MVC 或 DDD 层次，规定 DTO/VO/Entity 转化边界
   - 前端：定义 UI 组件库选型及数据交互规范，遵守AppleStyle风格
   - 数据库：强制索引设计逻辑（`id`, `create_time`, `update_time`, `is_deleted`），提供 DDL

2. **生成项目地图**
   - 技术栈清单（后端框架、前端框架、数据库、中间件等）
   - 后端、前端目录层级树状图（标注各目录职责）
   - 核心模块依赖关系图

3. **模块解耦**
   - 核心功能独立为 `docs/modules/[模块名].md`
   - 为每个核心模块生成 Mermaid 流程图（Sequence Diagram 或 Flowchart）
   - 提供配套 DDL 与测试数据（INSERT 语句）
   - 在主 `AGENT.md` 中建立引用索引

**输出产物：**
- `AGENT.md` - 项目架构主文档
- `docs/modules/*.md` - 各模块详细文档
- `docs/ddd/` - DDD 设计文档（如适用）
- `docs/database/` - 数据库设计文档

**参考资料：**
- 后端规范：[alibaba_java_guidelines.md](references/alibaba_java_guidelines.md)
- 图表规范：[mermaid_diagrams.md](references/mermaid_diagrams.md)
- AGENT.md 模板：[assets/agent_template.md](assets/agent_template.md)

### `/update` - 变更归档与同步

将开发过程中的变更归档到架构文档中。

**执行流程：**

1. **增量识别**
   - 自动捕捉 `CHANGELOG.md` 或项目末尾的临时变更记录
   - 识别代码变更对应的业务模块
   - 提取关键变更内容（新增功能、修改逻辑、删除废弃）

2. **逻辑重组**
   - 将临时记录重构并归档至对应的功能模块 `md` 文件
   - 更新模块的业务描述、数据流向
   - 同步更新主 `AGENT.md` 中的模块索引

3. **图表同步**
   - 分析业务逻辑变化对流程图的影响
   - 更新对应的 Mermaid 流程图（Sequence Diagram 或 Flowchart）
   - 验证图表逻辑与代码实现的一致性

4. **合规性检查**
   - 检查更新内容是否违反《阿里巴巴 Java 开发手册》规范
   - 检查命名、逻辑是否符合既定架构标准
   - 记录违规项并给出修正建议

**输出产物：**
- 更新后的 `docs/modules/*.md`
- 更新后的 `AGENT.md`
- 变更合规性报告（如有违规）

---

### `/enhance` - 架构进化评审

对架构优化建议进行多维度评审与迭代。

**执行流程：**

1. **深度评判**（三维预判）
   - **性能维度**：评估对系统吞吐量、响应时间、资源消耗的影响
   - **可扩展性维度**：评估对未来需求变化的适应性、模块解耦程度
   - **安全性维度**：评估引入的新风险、数据安全、权限控制

2. **冲突检测**
   - 分析新建议与现有系统设计的兼容性
   - 检查是否与数据库规范、架构分层原则冲突
   - 识别可能的技术债务

3. **自动迭代**
   - 评审通过后，全局更新 `AGENT.md` 及相关子文档
   - 重新生成受影响的 Mermaid 结构图
   - 输出架构变更摘要（影响范围、迁移路径、风险点）

**输出产物：**
- 架构评审报告（性能/扩展性/安全性分析）
- 冲突检测报告（如有冲突）
- 更新后的 `AGENT.md` 和 `docs/modules/*.md`
- 架构变更摘要文档

## 使用指南

### 适用场景

- **新项目启动**：执行 `/init` 建立完整的架构文档体系
- **日常开发**：每完成一个功能模块，执行 `/update` 归档变更
- **架构重构**：提出优化方案后，执行 `/enhance` 评审与迭代
- **技术审计**：定期执行 `/update` 检查代码与文档的一致性

### 前置条件

- 项目必须有清晰的目录结构
- 后端项目使用 Java（遵循阿里巴巴 Java 开发手册）
- 支持 Markdown 文档编辑环境
- 支持 Mermaid 图表渲染（如 VSCode + Mermaid 插件）

### 最佳实践

1. **增量更新**：避免一次性大量变更，频繁执行 `/update` 保持文档同步
2. **可视化优先**：核心业务逻辑必须有 Mermaid 流程图
3. **合规先行**：代码变更前先执行 `/enhance` 评审，避免技术债务累积
4. **持续重构**：定期检查 `AGENT.md` 与实际代码的一致性

## 技术约束

### 编码规范
- Java 代码必须符合《阿里巴巴 Java 开发手册》
- 禁止使用魔法值、Long 类型必须使用大写 `L` 后缀
- 异常处理必须捕获并处理，不能吞掉异常

### 图表规范
- 所有逻辑流程必须使用 `mermaid` 语法包裹
- 流程图优先使用 Sequence Diagram（时序图）
- 数据流向使用 Flowchart（流程图）
- 确保图表在 Markdown 编辑器中可直接渲染

### 引用格式
- 模块跳转使用 Markdown 相对路径链接：`[模块名](docs/modules/模块名.md)`
- 跨项目引用使用绝对路径：`[外部文档](../../other-project/docs/xxx.md)`
- 数据库表引用格式：`` `table_name` ``

## 进阶功能

### 多项目架构治理
支持在根目录创建 `projects.json`，管理多个子项目的架构文档：
```json
{
  "projects": [
    {
      "name": "backend",
      "path": "./backend",
      "agentDoc": "AGENT.md"
    },
    {
      "name": "frontend",
      "path": "./frontend",
      "agentDoc": "AGENT.md"
    }
  ]
}
```

### 架构版本控制
在 `AGENT.md` 顶部记录架构版本历史：
```markdown
## 架构版本历史

| 版本 | 日期 | 变更摘要 | 责任人 |
|------|------|----------|--------|
| v1.0.0 | 2026-01-01 | 初始版本，建立核心模块 | 张三 |
| v1.1.0 | 2026-01-15 | 新增用户权限模块 | 李四 |
```

### 技术债务管理
在 `AGENT.md` 中维护技术债务清单：
```markdown
## 技术债务

| 优先级 | 债务描述 | 影响范围 | 计划解决时间 |
|--------|----------|----------|--------------|
| P0 | 数据库未建立索引 | 所有查询接口 | 2026-02-01 |
| P1 | 用户服务未引入缓存 | 用户信息接口 | 2026-02-15 |
```
