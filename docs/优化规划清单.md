### 任务 2.1：线程安全优化 - 替换 new Thread() 为线程池

**当前问题：**

在 `AnalysisService.java` 中，使用 `new Thread()` 创建线程会导致：

1. **线程数量无限制**：大量并发请求时可能创建成千上万个线程
2. **线程重复创建销毁**：性能开销大
3. **无法优雅关闭**：应用关闭时线程可能仍在运行

**实现步骤：**

#### 步骤 1：创建线程池配置

```java
// backend/src/main/java/com/review/agent/config/ThreadPoolConfig.java
@Configuration
public class ThreadPoolConfig {

    @Bean("analysisTaskExecutor")
    public Executor analysisTaskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        // 核心线程数（CPU 密集型：CPU 核心数，IO 密集型：CPU 核心数 * 2）
        executor.setCorePoolSize(Runtime.getRuntime().availableProcessors());
        // 最大线程数
        executor.setMaxPoolSize(Runtime.getRuntime().availableProcessors() * 2);
        // 队列容量
        executor.setQueueCapacity(100);
        // 线程名前缀
        executor.setThreadNamePrefix("analysis-task-");
        // 拒绝策略：由调用线程执行
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        // 等待所有任务完成后再关闭线程池
        executor.setWaitForTasksToCompleteOnShutdown(true);
        executor.setAwaitTerminationSeconds(60);
        executor.initialize();
        return executor;
    }
}
```

### 任务 2.2：SSE 连接管理 - 添加心跳和连接限制

**当前问题：**

SSE（Server-Sent Events）连接可能出现：
1. **连接未检测断开**：客户端异常关闭后，服务端仍在保持连接
2. **连接数无限制**：恶意用户可能建立大量 SSE 连接耗尽资源
3. **连接超时未清理**：长时间无交互的连接占用资源

**实现步骤：**

#### 步骤 1：创建 SSE 连接管理器

```java
// backend/src/main/java/com/review/agent/common/sse/SseConnectionManager.java
@Component
@Slf4j
public class SseConnectionManager {

    // 存储所有 SSE 连接：userId -> SseEmitter
    private final Map<Long, SseEmitter> connections = new ConcurrentHashMap<>();

    // 最大连接数限制
    private static final int MAX_CONNECTIONS = 1000;

    /**
     * 添加 SSE 连接
     */
    public boolean addConnection(Long userId, SseEmitter emitter) {
        if (connections.size() >= MAX_CONNECTIONS) {
            log.warn("SSE 连接数已达上限，拒绝新连接，当前连接数：{}", connections.size());
            return false;
        }

        connections.put(userId, emitter);

        // 连接关闭时自动移除
        emitter.onCompletion(() -> removeConnection(userId));
        emitter.onTimeout(() -> removeConnection(userId));
        emitter.onError((e) -> removeConnection(userId));

        log.info("添加 SSE 连接，userId={}，当前连接数：{}", userId, connections.size());
        return true;
    }

    /**
     * 移除 SSE 连接
     */
    public void removeConnection(Long userId) {
        SseEmitter removed = connections.remove(userId);
        if (removed != null) {
            log.info("移除 SSE 连接，userId={}，当前连接数：{}", userId, connections.size());
        }
    }

    /**
     * 获取连接数
     */
    public int getConnectionCount() {
        return connections.size();
    }

    /**
     * 发送心跳到所有连接
     */
    public void sendHeartbeatToAll() {
        connections.forEach((userId, emitter) -> {
            try {
                emitter.send(SseEmitter.event().data("ping").name("heartbeat"));
            } catch (Exception e) {
                log.warn("发送心跳失败，userId={}", userId, e);
                removeConnection(userId);
            }
        });
    }
}
```

```java
// backend/src/main/java/com/review/agent/repository/DataInfoRepository.java

@Repository
public interface DataInfoRepository extends JpaRepository<DataInfo, Long> {

    // 软删除：将 deleted 标记设为 true
    @Modifying
    @Query("UPDATE DataInfo d SET d.deleted = true, d.deletedAt = :deletedAt WHERE d.id = :id")
    void softDelete(@Param("id") Long id, @Param("deletedAt") LocalDateTime deletedAt);

    // 查询时自动过滤已删除数据
    @Override
    @Query("SELECT d FROM DataInfo d WHERE d.deleted = false")
    List<DataInfo> findAll();

    // 按 userId 查询，自动过滤已删除
    List<DataInfo> findByUserId(Long userId);

    // 物理删除（慎用）
    @Modifying
    @Query("DELETE FROM DataInfo d WHERE d.id = :id")
    void hardDelete(@Param("id") Long id);
}
```

#### 步骤 3：修改 Service 层使用软删除

```java
// backend/src/main/java/com/review/agent/service/DataService.java

@Service
@RequiredArgsConstructor
public class DataService {

    private final DataInfoRepository dataInfoRepository;

    /**
     * 软删除数据
     */
    public void deleteData(Long dataId, Long userId) {
        // 验证权限
        DataInfo dataInfo = dataInfoRepository.findById(dataId)
            .orElseThrow(() -> new ResourceNotFoundException("数据不存在"));

        if (!dataInfo.getUserId().equals(userId)) {
            throw new ForbiddenException("无权删除此数据");
        }

        // 执行软删除
        dataInfoRepository.softDelete(dataId, LocalDateTime.now());
    }

    /**
     * 恢复已删除数据
     */
    public void restoreData(Long dataId, Long userId) {
        DataInfo dataInfo = dataInfoRepository.findById(dataId)
            .orElseThrow(() -> new ResourceNotFoundException("数据不存在"));

        if (!dataInfo.getUserId().equals(userId)) {
            throw new ForbiddenException("无权恢复此数据");
        }

        dataInfo.setDeleted(false);
        dataInfo.setDeletedAt(null);
        dataInfoRepository.save(dataInfo);
    }
}
```

### 任务 2.5：事务管理 - 添加 @Transactional 到关键 Service 方法

**当前问题：**

1. **原子性无法保证**：多步操作中任一步失败，其他步骤不会回滚
2. **并发问题**：可能出现脏读、不可重复读、幻读
3. **异常处理不当**：运行时异常可能导致数据不一致

**实现步骤：**

#### 步骤 1：识别需要事务的方法

| Service | 方法 | 需要事务的原因 |
|---------|------|---------------|
| UserService | register | 创建用户 + 初始化成就 + 记录日志 |

| CollectionService | addCollection | 创建合集 + 添加关联条目 + 更新统计 |
| QuizService | generateQuiz | 创建测验记录 + 生成题目 + 更新合集统计 |

#### 步骤 4：事务传播行为示例

```java
// 传播行为：REQUIRED（默认）
@Transactional
public void methodA() {
    // 如果已有事务，加入当前事务；如果没有，创建新事务
    methodB();  // 和 methodA 在同一个事务中
}

@Transactional
public void methodB() {
    // ...
}

// 传播行为：REQUIRES_NEW（创建新事务）
@Transactional
public void methodA() {
    // 在事务 T1 中执行
    methodB();  // 在独立的事务 T2 中执行，即使 T1 回滚，T2 也会提交
}

@Transactional(propagation = Propagation.REQUIRES_NEW)
public void methodB() {
    // ...
}

// 传播行为：NESTED（嵌套事务）
@Transactional
public void methodA() {
    try {
        methodB();  // 在嵌套事务中执行，可以单独回滚
    } catch (Exception e) {
        // 捕获异常，methodB 回滚，methodA 继续执行
    }
}

@Transactional(propagation = Propagation.NESTED)
public void methodB() {
    // ...
}
```

**验收标准：**
- [ ] 所有需要事务的方法都添加了 @Transactional 注解

**解决方案：批量查询**

```java
// ✅ 优化后：一次查询获取所有数据
public List<CollectionDetailVo> getCollections(Long userId) {
    List<AnalysisCollection> collections = collectionRepository.findByUserId(userId);

    // 一次性查询所有合集的分析结果
    List<Long> collectionIds = collections.stream()
        .map(AnalysisCollection::getId)
        .collect(Collectors.toList());

    List<CollectionRelation> relations =
        collectionRelationRepository.findByCollectionIdIn(collectionIds);

    // 按 collectionId 分组
    Map<Long, List<CollectionRelation>> relationsMap = relations.stream()
        .collect(Collectors.groupingBy(CollectionRelation::getCollectionId));

    // 组装结果
    return collections.stream()
        .map(collection -> {
            List<CollectionRelation> items = relationsMap.getOrDefault(collection.getId(), List.of());
            // 转换为 VO...
        })
        .collect(Collectors.toList());
}
```

#### 步骤 2：配置缓存

```java
@Configuration
@EnableCaching
public class CacheConfig {

    @Bean
    public CacheManager cacheManager(RedisConnectionFactory connectionFactory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofHours(1))  // 缓存 1 小时
            .serializeKeysWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new StringRedisSerializer()))
            .serializeValuesWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new GenericJackson2JsonRedisSerializer()));

        return RedisCacheManager.builder(connectionFactory)
            .cacheDefaults(config)
            .build();
    }
}
```
